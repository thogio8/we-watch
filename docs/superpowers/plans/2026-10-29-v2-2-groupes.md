# WeWatch 2.0 · Morceau 2 : groupes · Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** La liste unique devient une liste par groupe. On peut créer des groupes, choisir le groupe affiché par une pastille, swiper selon la règle « un oui suffit, un BOF ne vaut que pour soi », voir qui a fait quoi. La liste actuelle est copiée dans un groupe « NOUS DEUX », que rejoignent les comptes créés avec le code propriétaire.

**Architecture:**
- **Données.**
  - Les instantanés TMDB sont partagés : une ligne par film.
  - Chaque groupe a ses lignes de liste : statut, dates, auteurs.
  - Les « voulu par » sont stockés par groupe et par personne.
  - Les BOF sont stockés par personne, tous groupes confondus.
- **Groupe affiché.** C'est un cookie d'appareil, vérifié côté serveur contre les appartenances. Sans cookie, ou s'il est invalide, on prend le dernier groupe utilisé.
- **Actions serveur.** Chacune reçoit l'identifiant du groupe de façon **explicite** : la page le lie avec `.bind(null, groupId)`. Chacune vérifie la session **et** l'appartenance (`assertMember`).
- **Ancienne table.** La table `movies` reste intacte (migration additive). Elle sera supprimée en 2.1.

**Tech Stack:**
- Next.js 16.4 (App Router, Server Actions, `cacheComponents`).
- Drizzle 0.45 + libSQL, Better Auth 1.7.14.
- Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-28-wewatch-v2-design.md` : §6 Groupes, §8 liste/swipe/tirage, §9 pastille (option A), §10 (un ancien membre), §11 bascule, §12 sécurité, §13 morceau 2, §14 tests.

**Branche :** `feat/v2-groupes`, partie de `release/2.0.0` (morceau 1 fusionné). À la fin, une PR vers `release/2.0.0`.

**Plan du code existant :** `scratchpad/piece2-codemap.md`. Le contrôleur le copie dans l'espace de travail du plan : signatures, fichiers, pièges.

## Global Constraints

- **Migrations additives uniquement.**
  - `movies` n'est ni modifiée ni supprimée.
  - Les nouvelles tables sont créées et remplies par copie.
  - La migration doit tourner sans erreur sur une base vide (tests, e2e) comme sur la base de prod.
- **Groupe hérité :**
  - id `LEGACY_GROUP_ID = "nous-deux"`, nom `"NOUS DEUX"`, renommable plus tard (morceau 3) ;
  - créé par la migration **seulement si `movies` contient au moins une ligne**, pour qu'une instance neuve n'ait pas de groupe fantôme ;
  - aucun membre au départ.
- **Correspondance des statuts.** `to_watch` reste à voir. `watched` reste vu, avec `watched_at`. `rejected`, qu'il vienne d'un BOF ou d'un retrait, devient **écarté pour le groupe** (statut `rejected` de la liste du groupe). Les lignes copiées n'ont pas d'auteur (`legacy = true`).
- **Nom de groupe :** 1 à 30 caractères, mêmes règles de normalisation que le nom affiché (NFC, espaces réduits, rien d'invisible ni de contrôle).
- **Règles de swipe** (spec §8, à appliquer telles quelles) :
  - **ON LE VEUT** ajoute le film à la liste « à voir » du groupe s'il n'y est pas, et enregistre toujours « voulu par moi ».
  - **✕ BOF** vaut pour moi seul, dans tous mes groupes, sans jamais toucher la liste du groupe.
  - **Pile de swipe** : sont exclus les films de la liste du groupe (tout statut, écartés compris) et mes BOF.
  - **↺ ANNULER** défait seulement ce que ce swipe a créé.
  - **Recherche + AJOUTER** ajoute le film à la liste du groupe et efface mon BOF. Un film écarté redevient « à voir ».
  - **✕ dans la liste** écarte le film pour le groupe.
- **Attribution.**
  - Formules : « ajouté par Léa le 12 octobre », « voulu par Léa et Hugo », « vu le 18/10 · marqué par Hugo ».
  - Ligne copiée : « ajouté le 12 octobre », sans auteur.
  - Compte supprimé : « un ancien membre ». Les clés étrangères d'auteur sont en `onDelete: "set null"`.
  - « voulu par » liste les prénoms dans l'ordre des souhaits. Trois noms ou plus : « Léa, Hugo et Sam ».
- **Groupe affiché :**
  - cookie `ww_group` (`httpOnly`, `sameSite: "lax"`, `secure` en prod, 400 jours, `path: "/"`) ;
  - invalide ou absent → le groupe au `last_used_at` le plus récent, puis le plus ancien rejoint ;
  - aucun groupe → écran « CRÉER TON PREMIER GROUPE ».
- **Session de tirage par groupe** : la pile « pas ce soir » et les filtres. Clé de stockage `ww-tonight-v2:<groupId>`. Le groupe hérité relit `ww-tonight-v1` si sa clé v2 est absente.
- **Pastille (option A)** : « ● NOUS DEUX ▾ » au-dessus du titre de TIRER, SWIPER et LISTE.
  - Son panneau contient :
    1. mes groupes (nombre de membres, ✓ sur celui affiché) ;
    2. « + CRÉER UN GROUPE » ;
    3. « SE DÉCONNECTER », qui **quitte LISTE** pour venir ici.
  - « MEMBRES ET INVITATION » (morceau 3) et « MON COMPTE » (morceau 5) n'apparaissent pas encore.
- **Textes** (MAJUSCULES, typographie française ’ « ») : « CRÉER TON PREMIER GROUPE », « + CRÉER UN GROUPE », « NOM DU GROUPE », « CRÉER LE GROUPE », « TES GROUPES », « 1 MEMBRE » / « N MEMBRES », « UN NOM DE 1 À 30 CARACTÈRES ».
- Un compte créé avec le code propriétaire rejoint « NOUS DEUX » **dans la transaction d'inscription**, et seulement si ce groupe existe. Le lien « J’AI UN CODE PROPRIÉTAIRE » apparaît aussi en mode `open`, avec le code facultatif.
- **Sécurité :** chaque action et chaque page vérifie la session et l'appartenance. Un `groupId` forgé (lecture ou écriture) est refusé, sans aucune écriture.
- **Règles du dépôt** (`CLAUDE.md`) :
  - couches ESLint ; 200 lignes par fichier, 80 par fonction ;
  - jscpd et knip propres ; couverture ≥ 95/95/95/90, actuellement 100 % ;
  - `revalidate` après chaque écriture ;
  - `cacheComponents` : `cookies()` sous `<Suspense>` ;
  - DA riso, aucune couleur hors `tokens.css` ;
  - commits Conventional, header seul, en anglais, **sans trailer ni mention d'IA**.

## Review Focus

1. **Groupe d'un autre**, passé en argument d'action, en cookie, ou dans l'URL `/list/<id>` : la lecture retombe sur un groupe à moi, l'écriture est refusée, rien n'est écrit. → Tâches 4 et 5.
2. **Groupe changé dans un autre onglet** entre l'affichage et l'action : l'action porte sur le groupe **affiché** (`groupId` explicite), pas sur le cookie. → Tâche 5.
3. **Deux membres swipent le même film :**
   - deux « ON LE VEUT » donnent une seule ligne de liste et deux « voulu » ;
   - un « ON LE VEUT » et un « BOF » : le film est dans la liste, et le BOF ne le cache qu'à celui qui l'a mis.
   - → Tâche 3, plus l'e2e de la tâche 9.
4. **Annuler après qu'un autre membre a aussi voulu le film :** mon annulation retire seulement mon « voulu », la ligne reste. → Tâche 3.
5. **Migration sur une base réelle :** chaque film, statut et date est copié à l'identique ; base vide sans groupe fantôme ; `movies` inchangée. → Tâche 2.
